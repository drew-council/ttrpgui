# ttrpgui

Keyboard-driven app for planning and running TTRPGs. `SPEC.md` is the product spec; its "Architecture" and "Decisions" sections are binding.

The code MUST stay simple. Prefer the 200-line 90% solution over the 2,000-line perfect one. Reuse before adding. No speculative abstractions.

## Architecture

A headless Node server owns the Game directory and the one shared state tree. Clients are web pages it serves. Electron is a thin shell around both.

- `src/shared/schema.ts`: zod schemas for the on-disk formats and the user config. All strict: unknown keys are violations.
- `src/shared/state.ts`: the synced `GameState` and the socket messages.
- `src/shared/notes.ts`: note content rules shared by server and client: wiki link parsing (`parseLinks`, `renameLinks`, `backlinks`), `imageFile`, `mainImage`, and `noteLabel` (with `labelParts`), a note's title as people see it: a Session reads as its date and its name, else its title unless made from a date (`isDateTitle`), so a label never shows an ISO date. Every place that shows a note title uses it, except a wiki link in text, which shows only the name, else the date; pickers match the label and the title (`Item.title`). Plain text joins date and name with " · " (`noteLabel`); rows and tabs (`NoteName`) show the short date (`formatDate(iso, true)`: `Oct 11`, or `Dec 20 ’25` in another year), muted when a name follows. `sessionOrder` sorts Sessions newest first, the later title first within a day; quick open and "Linked from" list Sessions first in that order. Never parse links anywhere else.
- `src/shared/statblock.ts`: ability modifiers and the text forms of bonuses (`Dex +6, Con +8`), as shown and as typed.
- `src/shared/dice.ts`: the one dice and arithmetic language: `parse` (while typing; unfinished input still returns its entries, with a `hole` where more is needed), `rollAll` (on Enter, with an injectable `random`), `rollDie` (also for initiative), `value`, `hasDice`. See "Dice". Unit tested.
- `src/shared/combat.ts`: the pure combat rules over Combat data: turn order, turns, per-Combatant `rules` (damage, conditions, ...), initiative rolls. `canFight`: Creatures and vehicles may be Combatants; a vehicle fights as an NPC. Unit tested.
- `src/shared/display.ts`: the pure display rules: track names (`parseTracks`), the active Atmosphere, playlist shuffle (`nextTrack`: every track once per pass), switching around combat, and `playerTracker`, the one place that decides what players may see. Unit tested.
- `src/shared/keys.ts`: every `Action` id with its default bind, the key syntax (`ctrl+k`, `shift+g` or `G`, `j`, `+`, `f2`; alternatives separated by spaces: `= +`), and `binds(config.keys)`, the user config over the defaults.
- `src/server/game.ts`: `loadGame` loads and validates the Game in one pass; a file with problems loads its valid parts and reports only its schema problems; `loadConfig` does the same for the user config; `reconcile` for reloads; `searchNotes` for full-text search.
- `src/server/mutations.ts`: mutations, the only way clients change the Game. Each one edits files. Metadata, stat block, and atmosphere writes go through `saveToml`: it validates against the schema and refuses to overwrite a file that has problems. Combat mutations wrap `combat.ts` rules with `onCombat`/`onCombatants`, which also keep undo history. See "Combat".
- `src/server/download.ts`: runs `yt-dlp` for an Atmosphere's links, outside the mutation queue. Wallpapers are SDR only. A failure that looks like YouTube wants sign-in says how to fix it.
- `src/server/server.ts`: `startServer({ gameDir, configFile, host, port })`. HTTP (built client, Game files under `/game/`, and `/search?q=`). `gameRequest` decodes each `/game/` path segment fully before sirv sees it, so any file name works, WebSocket sync on `/ws`, and the file watcher. MUST stay Node-compatible: no Bun or Electron APIs.
- `src/cli.ts`: `serve` and `validate`. `src/electron.ts` and `src/preload.cjs`: the start page, then the server in-process, the control window, and the display window (the control page learns whether it is open: `onDisplay`, kept in `ui.display`). `electron.ts` also disables Chromium's Wayland color management (`WaylandWpColorManagerV1`): with it, Hyprland hands a fullscreen window HDR and switches the monitor into HDR.
  - Start page: `/start` of the same client (`Start.tsx`), served by a loopback `sirv` before any Game server exists. The one control window moves between the start page, a local Game, and a remote one; `mode` in `electron.ts` decides what the preload exposes (`bridge.ts` types it): `start` on the start page, `display` and `onDisplay` for a local Game, `back` everywhere. Hosting a display serves on `0.0.0.0` and swaps the control window for the display window, fullscreen (through the page's own Fullscreen API, so F leaves it) and titled `<Game> display — ttrpgui`, and closing it quits; a normal open stays on loopback. Joining opens the control window on the remote URL. `back` closes the local server and the display window. A hosting display's URL carries `?join=` (`joinAt` in `start.ts`), which `Display.tsx` shows beside the fullscreen hint, with "Close this window to stop hosting". The control window's title names its Game, and for a joined one its host. A server joins recents only once it answers `/info`.
  - `src/start.ts`: no Electron: recents (`$XDG_STATE_HOME/ttrpgui/recent.json`, Games with their last mode and servers, `remember`), `serverUrl`, and discovery: `GET /info` to each address in this computer's private /24s on `--port` (default 7373), 700 ms timeout, one row per host and port. `TTRPGUI_DISCOVER` replaces the targets in tests. Unit tested.
  - Flags skip the start page: `--game`, `--display`, `--lan`, `--connect URL`. `--port` alone does not. `loadWhenUp` loads a window once its server answers and until then shows `/waiting` (the Game's name when known, the reason, and Escape back to the start page with that address in its field and the reason beside it); a join loads only a server whose `/info` says ttrpgui, and one that answers as something else, or a name that does not resolve, stays on the start page with the error. The preload's functions pass on only their own parameters, so a click event never reaches IPC. `--display` is also Chromium's X11 display switch, under which GTK dialogs crash, so `electron.ts` removes it from Chromium's command line.
- `src/client/`: one React app (Vite). `/control` → `Control.tsx`, `/display` → `Display.tsx`.
  - `sync.ts`: the state mirror. `useGame(selector)`, `getGame()`, `useStatus()`, and `send(mutation)`, which resolves `true` once applied or toasts the error and resolves `false`.
  - `ui.ts`: per-client state (tab groups, their tabs' history, mount keys, and places, sidebar, picker, confirmation, open menu, dice roller) in a tiny store from `store.ts`. Tab groups, their history, the sidebar, and the pickers' recent lists persist in localStorage. That needs the same origin each launch: the Game server's default port is fixed. `toast()` shows a Sonner toast, text or markup, under the popups. See "Tabs" and "Zoom".
  - `history.ts`: the pure per-tab back and forward history, and the recent lists (`remembered`, `recency`). Unit tested.
  - `groups.ts`: the pure tab groups (`Groups`): `placed` (move a tab into a group or a new one), `without` (close), `restored` (saved state, the old single list as one group). Unit tested.
  - `actions.ts`: the `Action` registry (title, `when`, `run`, and for its GUI control an `icon` and short `label`), keybind dispatch, and the mouse's back and forward buttons. `controls.tsx`: the GUI form of an Action. See "Controls". `Picker.tsx`: the one fuzzy picker (shadcn Command in a Dialog; fuzzysort ranks and highlights, cmdk's filter is off), also used for prompts. A spec with `recent` (a list name in `ui.recent`) lists the rows chosen most recently first while the query is empty, and breaks ranking ties by recency; choosing a row from `items` records its `key`, else its label; `current` names a row that never leads. Opt in only lists chosen from again and again, not ones whose order means something (by date, today's session first) or short fixed ones. Quick open's list is `tabs`: `ui.ts` records each tab shown, and `replaceTab` renames it. `Confirm.tsx`: the one yes or no dialog (shadcn AlertDialog, placed and styled like the picker): `Y` confirms, `N` and Escape cancel, Enter and Space press the focused button, which starts on the safe one; arrows and Tab move between the two, and buttons say what they do. While it or a menu is open, no keybind runs but the privacy screen's (`blocked` in `actions.ts`). The start page uses it too. `list.ts`: the one list behavior (`j`/`k`, arrows, `g`/`G`, Enter, Ctrl+Enter for a new tab) and its classes (`listClass`, `rowClass`).
  - `MarkdownBox.tsx`: the one markdown text box (CodeMirror 6). See "Text editing".
  - `views.tsx`: tab views (note, combat, atmosphere, problems), and their panes (see "Tabs"). The note view holds the body's `MarkdownBox`, then its images and backlinks as lists. A Creature or vehicle adds an aside with its portrait and `StatBlock`; a Creature's meta row holds its pronouns, a `SaveInput` that reads as text at rest and that `set-pronouns` focuses (`pane.pronouns`); a Location shows its main picture, a vehicle its maps under the text, full width; a note's title is a `TitleField` that renames it (`renameNote` in `actions.ts`; one line, an ellipsis at rest; Enter or Tab saves and focuses the view's main element; a refused name stays with focus, and only Escape or a blank name reverts), as a Combat's and an Atmosphere's are. F2 (`rename-note`, `rename-combat`, `rename-atmosphere`) focuses and selects it (`pane.title`). A Session's title is its name field instead (Enter or Tab saves and moves to the text, Escape reverts; unnamed, it shows the date in words), which F2 focuses; its date is a button that opens a calendar under it (shadcn Calendar in a Popover; weeks start Sunday; Today and Clear; open, it sets `ui.menu`, so no keybind runs but the privacy screen's; closing returns focus where it was), which `set-session-date` opens (`pane.calendar`), and it lists its combats. New session focuses the name. Header Actions sit on the line under the title, the rest in a ⋯ menu. `Sidebar.tsx`: notes grouped by kind, and combats, each group with a + that creates one; `focusSidebar()`. Groups collapse (`ui.collapsed`, persisted); headers are list stops except while filtering, and stick while their rows scroll. `h`/`l` collapse and expand. The filter opens every group with a match. The active row, or a collapsed group's header holding it, sits in the page color with its kind's mark; hover is lighter. A stuck header shows a hairline (CSS `scroll-state`). The cursor shows while focus is anywhere in the sidebar, the filter included. Its + expands a group. When the active tab changes, its row (or its collapsed group's header) scrolls into view, and `focusSidebar` puts the cursor there. Dates take a wider column while any Session is from another year.
  - `Bar.tsx`: the table bar along the bottom, the game master's remote. Two ends set apart by quiet space, groups within them by space alone, no boxes or dividers. The left: the screen (display window toggle, atmosphere switcher), the table (Go live, or the live session's name with a menu to open or end it; the running combat), the shown image (a thumbnail and its note's name), then trouble (Reconnecting…, problems); showing or hiding an image moves nothing before it. The right, pinned so the buttons never move: the track, play or pause, skip, mute, volume, then the dice roller, the privacy screen, and the palette. The music Actions' `when` and `unavailable` decide what is disabled and why; the bar only renders. A cell before the track holds a state word ("Paused", "Muted", and in Electron "Display closed", since only the display sounds; that one opens the display). It always holds room for "Paused", at the outer edge where empty room reads as the quiet space, so pausing or muting moves nothing at any width. As the bar narrows, `fit` hides names in a fixed order, each readable or gone, never a stub: the artist, the session (leaving "Live"), then the image, then the combat; then the atmosphere and track shrink to a floor; last the track goes, and the state word with it. Names are foreground only for the atmosphere and the track; amber marks only what is live. Text beside icons uses `capText` (`controls.tsx`, also in `ToolButton`): the UI font sits high in its line box. "Back to the start page" lives on the empty tab (`Welcome`).
  - `Tracker.tsx`: the combat view (toolbar on top; tracker left; the cursor's note and `StatBlock` right) and the helpers tracker Actions use: `target()` (in the active view's tracker, `pane.tracker`, the selection, else the cursor row), `askNumber` (see "Dice"), and the add-combatant and condition pickers.
  - `Dice.tsx`: `<Dice expr times? total? />`, the one rendering of a dice expression, typeset or rolled: each die's face where its term sits, dropped dice struck through, a d20's 20 green and its 1 red, division in floor brackets, a hole as a faint `…`, a missing `)` faint. The total, or else a `note`, sits in a right-hand column on the first line; a plain number shows none. A rolled row shows each dice-free part as its value (`5d10 [faces] − 1`). Lining figures; dropped dice are outlined chips, struck through. `<Rolls roll />` is one entry of the roller's list under its label, its rows numbered when it holds several.
  - `Roller.tsx`: the dice roller popup (`roll-dice`, `openRoller` in `ui.ts`), styled like the picker. Its rolls live in `ui.rolls`, capped and in memory only; `addRoll` (`ui.ts`) adds one, from the roller or a number prompt, and the new row fades in. Up and Down recall earlier texts; Down past the newest brings back the draft. The preview stays while typing: an unfinished input shows its holes, with the parser's message muted in the last row's total column, so the area grows only with the number of rolls; a wrong one shows its message in the error color; Enter on either shows it as an error. A Roll button rolls as Enter does. PageUp and PageDown scroll the rolls from the input; a roll scrolls them to the top.
  - `Display.tsx`: the player display. On `/display`, one rem is 1/54 of the screen's short side times the page zoom (`applyZoom` in `ui.ts`), so every size scales to any screen. It handles F and the zoom binds itself (`zoomOnKey` in `ui.ts`, which the start page uses too). `Fade` crossfades the wallpaper and the shown image (`data-layer`).
  - `PrivacyScreen.tsx`: the opaque cover the `privacy-screen` Action raises over the control window (`ui.privacy`, in memory). Window capture listeners swallow every key and click while it is up and lift it on the first non-modifier key or click; that key's repeats and release are swallowed too. Focus never moves. Turning it on closes the picker; an open menu stays under it.
  - `Atmospheres.tsx`: the atmosphere tab view.
  - `StatBlock.tsx`: `<StatBlock title={t} editing? />`, the one stat block, read-only or as a form with the same rows. Fields save on blur; edits run one at a time so each builds on the last. Whether a note's form is open is its view's own state (`pane.statblock`). The section and entry Actions act at `formCursor()`, read from where focus is. Also `SaveInput`, the one-line field that saves on blur, and `fieldBox`, the classes that make a box around a `MarkdownBox` look like an input.
  - `components/ui/`: vendored shadcn/ui components. See "Styling".
  - `theme.css`: the one theme (Tailwind, shadcn's variables, the app's tokens). `markdown.css`: CodeMirror content styles. There are no other stylesheets.
- `harness/`: Playwright helpers for agents. `fixtures/sample-game` is a realistic Game; `fixtures/broken-game` holds one of each violation.

Node 24 and Electron 45 run the `.ts` sources directly (type stripping). Only the client is built. Imports use explicit `.ts` extensions, and TypeScript MUST stay erasable (no enums, no namespaces, no parameter properties).

## Sync

Files on disk are the truth. State is always the result of loading them: the server mutates state only with Immer `produceWithPatches` around `reconcile`, which diffs a fresh `loadGame` against state, so only real changes produce patches. A new client gets a snapshot, then patches. Nothing is optimistic.

A mutation edits files, then the server reloads and answers the sender after broadcasting the patches. Any outside change in the Game directory or the config file triggers the same debounced reload; reloading files the server just wrote is a no-op. Mutations and reloads run one at a time through a queue. Note bodies are not in state: fetch `/game/notes/<Title>/note.md` and refetch when `bodyVersion` changes. Images are served from the same path. Every client URL of a Game file comes from `gameUrl` (`Display.tsx`), which encodes each segment with `encodeURIComponent`. Each note's outgoing link titles (`links`) are in state, so backlinks need no fetch.

The user config (`$XDG_CONFIG_HOME/ttrpgui/config.toml`, a `[keys]` table of Action id to bind, `""` to unbind) is part of state, so every client gets the same binds. Its problems join the Game's.

## Combat

A Combat is `combats/<Name>.toml`; Combatants reference Creature or vehicle notes by title (key `creature`) and own only their state (labels are keys). Base max HP and AC always come from the stat block. A PC's HP lives in its `metadata.toml` `hp` table: `onCombat` copies it onto the Combatant for the rule, then writes it back, so rules never care. `runtime.toml` holds the live Session and the running Combat. Renaming a note rewrites references in both.

Undo: before a combat mutation writes, `onCombat` records what each file it changes held (a PC's metadata included); undo restores them and records the reverse for redo. One stack per Combat, in server memory. Combat creation, rename, and deletion are not undoable; renaming a Combat, or a note it references, clears its history, since entries name files.

Tracker Actions use `onTracker` in `actions.ts`: from the keyboard available only while the tracker has focus, from the combat view's toolbar always; both act on `target()`. Shift+click toggles a row's selection.

## Display and atmospheres

An Atmosphere is `atmospheres/<Name>/`: an optional `atmosphere.toml` (links, `default`), `wallpaper.<ext>`, and `music/`. Playback only uses those files; `syncAtmosphere` starts `download.ts` and returns at once, files appear through the normal reload, and `notify` toasts how it ended. Partial downloads stay in dot directories, which the loader and watcher ignore.

`runtime.toml` holds the active Atmosphere, what End restores, the shown image, and the music (track, paused, volume). The display client plays the track and sends `nextTrack` when it ends, when it fails to play (until three skips in a row have failed), or when no track of the active Atmosphere is current; the server shuffles. The played set of each Atmosphere's pass is server memory (`played`), so switching back continues the pass. Track art that fails to load shows what no art shows (`Img` in `Display.tsx`). Audio plays only on `/display`. Renaming or deleting a note or Atmosphere rewrites `runtime.toml` and Combats.

## Dice

`dice.ts` reads every number the user types for a roll or an amount; nothing else parses them. `NdM`, `kh`/`kl` (`k` alone is `kh`), integers, `+ - * /`, parentheses, unary minus; `/` rounds down at each division. A leading minus negates the whole term (`-7/2` is −3); after an operator or `(` it binds to its number. A top-level comma list and `Nx expr` or `expr xN` are separate rolls; `x` without dice is an error. Parse while typing, roll on Enter. `showNumber` writes a negative number with a real minus sign and groups digits.

- `askNumber` is the one number prompt. `label` gets the number as text (`showNumber`). A number shows its value in the row (`label(n)`) and is refused below `min`; dice-free arithmetic also shows its typeset form, quieter. Dice, and any unfinished input, show the typeset expression in the row (`label` gets a placeholder string and `Dice` takes its place) with "Enter rolls" on the right, or the parser's message while unfinished. Wrong input shows its message in the error color. Dice roll once on Enter and apply the total raised to `min`. The roll goes to the roller's list (`addRoll`) and a toast with its dice area capped, showing the applied total, labeled with what it did, `subject` (who or what it affects), and the raw total when it was raised. A list is refused. A refusal is a disabled row (`Item.disabled`); a row with markup uses `Item.view`.
- Rolls never reach the server or the display. Stat block fields stay plain numbers (`toInt`).

## Text editing

All text editing MUST use `MarkdownBox`: `<MarkdownBox value={text} onSave={(t) => send(...)} />`. Optional: `imageBase` (URL that relative image paths resolve against), `onImage` (store a pasted or dropped image, resolve to its path), `placeholder`, `view` (a ref to the `EditorView`). Without `onSave` it is read-only.

- The text is plain and round-trips byte for byte. Live preview is decorations only: markup hides unless the cursor touches it.
- It saves 500 ms after typing stops, on blur, on unmount, and before unload. A new `value` that echoes one of its own saves is ignored. Any other new `value` replaces the text with a minimal change, so the cursor stays; unsaved edits lose to it.
- `[[` completes titles. A link shows its label; a missing target looks dashed. Click or `follow-link` (Alt+Enter, Ctrl+Alt+Enter for a new tab) opens it, creating a plain note if missing.
- Images use relative markdown (`![](file.png)`) and render inline. A pasted or dropped image goes through the `addImage` mutation into the note directory. Roles live in `metadata.toml` (`setImageRole`).
- Tab and Shift+Tab indent. Escape focuses the box itself (Enter returns), and the next Tab moves past the editor.

## Tabs

A tab id is `view:arg` (see `views.tsx`); an empty tab is `new:<random>`, whose view shows the welcome hints. Ids are unique across groups, so opening something already open switches to its tab.

- Tabs live in tab groups, side-by-side columns (`ui.groups`, `groups.ts`), each with its own tab bar and active tab. "Pane" means one tab's mounted view, never a group. Exactly one group is focused (`ui.focus`); `activeTab()` (`ui.ts`) is its active tab, the one Actions act on. Focus or a press in a group focuses it (`focusOn` in `Control.tsx`); a press moves focus into its pane at once, before it acts, and a press on nothing focusable leaves focus where it is rather than on the pane. Its active tab's marker shows in full, the others' muted; a pane outside it carries `data-unfocused`, and its view mutes its cursors with `in-data-unfocused:`. A group goes when its last tab does, and focus moves to a neighbor; only a lone group is empty. Groups share the width. A split, move, or drop that would make a group with no room, under `minGroupWidth` (22rem, `ui.ts`), is refused (`change`): a drop shows no tint, and the Actions stay available and toast why (`regroup`). Open groups shrink to `groupFloor` (18rem), then the group area scrolls sideways; the focused group scrolls fully into view whenever it takes focus, a tab opens, or the groups change. A wheel over a tab bar scrolls it sideways.
- `openTab(tab, newTab)` is the one way to open anything: a tab open in any group shows there and focuses that group; a tab not yet open replaces the focused group's active one, or opens beside it when `newTab`. `newTab()` opens an empty tab beside the active one.
- Each tab has a history (`history.ts`), kept in `ui.ts` by tab id: when a plain open replaces a tab, the old id goes on its back list and forward clears. A new tab, or a filled empty tab, starts with none. `travel` (the `go-back` and `go-forward` Actions, the tab bar arrows, Alt+Left/Right, mouse buttons 3 and 4) shows the nearest entry that exists and is not open in any tab of any group, and passes over the rest, which stay for later. `closeTab` drops a tab's history; `replaceTab` renames through every history. `MarkdownBox` leaves Alt+Left/Right to the app.
- Every open tab's view mounts in its own pane (`TabPane` in `Control.tsx`) when it first shows and stays mounted; only each group's active one shows, so a tab shown again finds its scroll positions, focus, editor state, and forms as it left them. A hidden pane skips rendering (`content-visibility`, not `display: none`, which loses scroll offsets) and is `inert`: it takes no focus, keys, or clicks. It still follows synced state. A hidden view MUST NOT focus, scroll, or toast; check `checkVisibility()` before scrolling from an effect. Closing a tab unmounts its view. A view that unmounts leaves its place by tab id (`savePlace` in `ui.ts`, in memory, the 100 latest): its pane's scroll offset, or with its main text box (`pane.editor`) at the top, the position there and how far below it, since a text box laid out again estimates the heights of lines it has not drawn; that text box's selection; a tracker's cursor and selection, which `CombatView` takes as it mounts. When that tab mounts again (Back, Forward, reopened), `restorePlace` (`views.tsx`) puts it back as its content lays out and grows and its text box measures lines, until the user scrolls, presses, or types, or two seconds pass; a search result's `reveal` wins. `replaceTab` carries it. Panes render in one flat list in mount key order, each placed in its group's grid column by CSS, so moving a tab between groups, or making or closing a group, moves and remounts nothing. An absolutely placed grid item MUST name both column lines, or it stretches to the container's edge.
- A pane mounts under `mountKey(tab)` (`ui.ts`), which `replaceTab` carries to the new id, so a rename keeps the view: the view gets the new `arg` as a prop. A rename's tab follows as soon as synced state shows it (`followRename` in `actions.ts`), so the view never sees its target missing. Until the rename lands, mutations a view sends name their target with `paneArg(pane)`, and tab Actions wait for it, since the server applies mutations in order. A note's text refetches only when `bodyVersion` changes.
- A pane is a plain object a view fills in through `usePane()`: its main element (`useTabFocus`), title field, tracker, stat block form. `activePane()` (`views.tsx`) is the pane Actions act on, the focused group's active tab's; every lookup of "the" view goes through it, never a module-level variable or a document-wide query. Lookups that start from focus (`formCursor`, `linkUnderCursor`) need neither, since focus is only ever in a shown view, and that view's group is the focused one.
- Dragging a tab moves it: native drag and drop, the tab id under the `tabDrag` type (`Control.tsx`), so any drop target can read it, and in `ui.drag` while dragged, since a drag's data is unreadable until the drop. A tab bar shows an insertion mark (a short light bar, unlike the active tab's amber stripe) and calls `moveTab(tab, group, gap)`, over `placed`; histories stay. While a tab is dragged, a `DropZone` covers each group's content: its outer quarters make a new group on that side, the middle of another group moves the tab to its end, and the half or whole it would fill tints. A drop that changes nothing (`sameGroups`) is refused. `move-tab-left` and `move-tab-right` move the active tab within its group; `split-right`, `move-tab-to-next-group`, and `move-tab-to-previous-group` move it between groups (`splitMove`, `groupMove`), and `split-right` on a group's only tab opens an empty tab in the new group; each tab bar ends with a `split-right` button; `focus-next-group` and `focus-previous-group` focus one. `next-tab` and `previous-tab` cycle within the focused group.
- Every mouse open goes through `clickOpens(open)` (spread on the row): a click opens, Ctrl/Cmd+click or a middle-click opens in a new tab, and a middle press does not paste the primary selection. Code that sees the raw event (the picker, wiki links in `MarkdownBox`) uses `wantsNewTab(e)`. Keyboard: Enter, and Ctrl+Enter for a new tab, in `useListNav` and the picker.

## Zoom

Each page zooms alone through its root font size (`zoom`, `applyZoom` in `ui.ts`), stored per page in localStorage. Native zoom would not do: Chromium shares it per origin, so both windows would zoom together. Sizes MUST be in rem (Tailwind spacing and text sizes) so they scale; px is only for hairlines, radii, and shadows.

## Focus

Where focus sits decides which keys work. Code moves focus by ref, never with a document-wide query.

- A view's `Body` names its main element once with `useTabFocus(() => ref.current?.focus())` (`views.tsx`). `TabPane` focuses it when the tab is opened, and again each time `openTab` opens the tab while it shows (it bumps `refocus` in `ui.ts`). When a tab shows in the focused group, or its group takes focus, focus goes back to the element in it that last had focus (`focusAgain`, which gives an editor back its selection), else to the main element, unless a click already put focus in it. With no main element, the pane itself takes focus (`focusMain`), so focus never falls to the page body. `ui.ts` knows nothing about views.
- A note's wrapper passes focus to its editor. Until the text loads it holds focus, and hands it over on load only if focus is still there.
- A tab opened fresh starts at the top; one that comes back finds its place (see "Tabs"). Nothing scrolls a pane by focusing: focus moves with `preventScroll` (CodeMirror's focus already does), `closePopup` and `ActionMenu` included.
- The picker, a confirmation, and the dice roller are one popup at a time: `pick`, `confirm`, and `openRoller` replace the others, and the first to open remembers what had focus. `closePopup` unmounts the dialog with `flushSync` (Radix traps focus while it is open), then returns focus there. If that is gone or hidden, as after Ctrl+Tab under the popup, `TabPane` focuses the focused group's shown view instead (`focusPane`: its last focused element, else its main element). The chosen item's `run`, or a confirmation's `run` or `cancel`, may then move it.
- Controls never take focus on a press (see "Controls"). A tab does, since refusing it would stop it dragging; a click or a drag's end hands focus to the shown view (`focusPane`). Its × never takes focus. The combat toolbar focuses the tracker on a press unless it has focus, so tracker keys work after it.
- Leaving goes back by ref: Escape in the combatant note focuses the tracker; closing the stat block form focuses the note's text box.

## Controls

Buttons and menu items run Actions; they never reimplement one. `controls.tsx`:

- `<ActionButton id />`: icon, plus text when the registry has a `label`; a tooltip with the title and current bind; disabled while unavailable, with the Action's `unavailable()` reason under the title (a disabled button sits in a span so its tooltip still shows). `label`, `icon`, and Button props (`variant`, `className`, `tabIndex`) override. `ToolButton` is the same button for the few controls that are not Actions (an image row's show, the running combat).
- `<ActionMenu>` is a "More" (⋯) menu, or takes a `trigger`; `<ActionItem id destructive? />` is its item, with the bind as the shortcut. While it is open, `ui.menu` is set and no keybind runs; the menu's own keys work. The chosen item runs after the menu closes and focus is back where it was before it opened (`afterMenu`), so the Action sees what the keyboard would and a picker returns focus there.
- `useAvailable(id)` rerenders on synced state, `ui`, and focus changes. Controls ask `canRun(id, true)`: `when(true)` skips checks that only decide where keys go (tracker focus), since the control's place already says it. A control in a tab group (`GroupContext`: its tab bar and panes, menus included) asks as if its group had focus (`asFocused` in `ui.ts`), since a press there focuses the group before it acts; so it never looks disabled, or needs a second click, because another group has focus. Elsewhere (the table bar, the palette, keys) Actions act on the focused group.
- Neither takes focus on a press, so stat block form buttons act at the focused field and tracker Actions keep their target.
- Disable a control that does not apply now, so a toolbar does not jump; hide one that can never apply here (display controls outside Electron). Where two Actions alternate (start or end combat, PC or NPC), show the one that applies.
- Space is scarce at 1280x800: icon buttons with tooltips, text only where the icon is unclear, the rest in the ⋯ menu.

## On-disk format

`<game>/notes/<Title>/` holds `note.md`, an optional `metadata.toml` (kind, roles, and so on), an optional `statblock.toml`, and images. `<game>/combats/<Name>.toml` and `<game>/runtime.toml` are described under "Combat", `<game>/atmospheres/<Name>/` above. `schema.ts` is the truth; README's "Game directory format" documents it for people and agents and MUST stay in step. Dotfiles are ignored.

## How to

- **Add a mutation:** add a function to `mutations` in `src/server/mutations.ts` that edits files. Its payload type becomes part of `Mutation` automatically. Throw to reject; the client toasts the message.
- **Add a combatant operation:** add a rule to `rules` in `src/shared/combat.ts`, a line `name: onCombatants(rules.name)` to `mutations`, and an Action (`sendFor`, `amount`, or `onTracker`).
- **Add an Action:** add its id and default bind (`""` for none) to `defaultKeys` in `src/shared/keys.ts`, then its title, optional `when` (and `unavailable`, the reason a disabled control shows), and `run` to `actions` in `src/client/actions.ts`. TypeScript enforces that both lists match. It appears in the palette automatically. If someone would look for it on screen, give it an `icon` (lucide), a `label` if the icon alone is unclear, and put `<ActionButton id="..." />` or `<ActionItem id="..." />` where it belongs (see "Controls"). Use `pick()` for any choice, `confirm()` for a yes or no question, and `ask()` for text input (`load` fetches rows per query, as search does). `onNote`, `inCombatTab`, and `inAtmosphereTab` make an Action on the active tab; anything else about the visible view comes from `activePane()`. `confirmDelete` is the shared deletion prompt; its `detail` says what goes with it.
- **Add a view:** add an entry to `views` in `src/client/views.tsx` (`Label`, `Body`, optional `exists`; `Body` renders only while `exists`, so it need not handle a missing target). Its `Body` calls `useTabFocus` if it has a main element to focus, and puts what Actions need from it on `usePane()`. It mounts when its tab first shows and stays mounted while its tab is open, hidden or not, in any group, and its `arg` can change under it (a rename), so key fetches and effects on what changes content, not on `arg`. Open it with `openTab("<view>:<arg>")`. Lists inside it use `useListNav` with `listClass` and `rowClass`.
- **Add a sidebar group:** add an entry to `groups` in `src/client/Sidebar.tsx` that returns tab ids, and the `create` Action its + runs.
- **Add a file type** (for example `atmospheres/*.toml`): add a strict schema to `schema.ts`, load it in `loadGame` with `readToml` (it reports problems), add its key to `GameState`, and allow its path in `loadGame`'s top-level entry check. Mutations write it. Add a broken case to `fixtures/broken-game` and to the validator test.

## Styling

Tailwind CSS 4 and shadcn/ui (Radix, cmdk, Sonner, lucide icons). `src/client/theme.css` is the one theme: the CSS variables shadcn components read (`--background`, `--primary`, `--muted`, ...) and the app's own tokens (`--faint`, `--kind-*`, `--select`, and the display's `glass` and `glow`), all exposed as utilities (`bg-primary`, `text-faint`, `bg-kind-pc`, `font-serif`, `bg-glass`, `text-shadow-glow`). The app is dark only; `index.html` sets `class="dark"`.

- If shadcn has a component for the job, use it; never write a custom equivalent. Add one with `bunx shadcn add <name>`. It lands in `src/client/components/ui/` and is imported as `#components/ui/<name>.tsx` (`package.json` `imports`, which Vite and TypeScript resolve natively). Those files are vendored: Biome formats them but does not lint them, and they change only for theming. Style a use with `className`, not by editing the component.
- Everything else is Tailwind utilities in JSX, merged with `cn` from the `cn` package. No new CSS files. Share a class string as a constant only when it truly repeats.
- `markdown.css` styles CodeMirror content and decorations, which utilities cannot reach. It is unlayered so it outranks CodeMirror's own theme, and it reads theme variables. Since utilities cannot override it, a wrapper opts in with a styling class: `note-body` (tall text box), `md-small` (stat block and combatant note text), `md-entry` (an entry name, from `--name`, runs in before the text).
- Shared: `ActionButton`, `ToolButton`, `ActionMenu`, and `ActionItem` (`controls.tsx`), `listClass` and `rowClass` (`list.ts`), `page`, `pageTitle`, and `pageMeta` (`views.tsx`), and `fieldBox` (`StatBlock.tsx`). `Section` (`views.tsx`) is the titled block under a page. Chips are shadcn `Badge`; the kind lozenge is `KindMark`.
- Class names are for styling only. Code finds elements with refs, or with `data-*` attributes when the lookup crosses components (`data-tracker`, `data-statblock`, `data-section`, `data-entry`, `data-picked`, `data-turn`, `data-layer`). Tests use roles, labels, and these attributes.
- Radix overlays trap focus and catch keys. The picker turns off cmdk's vim keys so app binds still fire; see "Focus" for `closePopup`.

## Commands

Run inside the dev shell (`direnv allow`, or prefix with `nix develop -c`). Biome, Electron, Xvfb, and the Playwright browsers only exist there.

- `bun start [-- --game DIR]`: build the client and launch Electron: the start page, or with `--game` that Game. `--display`, `--lan`, `--connect URL`, and `--port N` as in README "Install".
- `bun run dev`: Vite with hot reload, plus the game server on port 7373. `GAME=DIR` picks the Game; the default is a temp copy of the sample.
- `bun run cli serve --game DIR [--port N] [--lan]` and `bun run cli validate DIR`.
- `nix build`: the package (`nix/package.nix`): `result/bin/ttrpgui` (Electron on `result/share/ttrpgui`) and `ttrpgui-cli`. After a dependency change it fails with a hash mismatch on `ttrpgui-node-modules`: put the `got:` hash in `nix/package.nix`. `TTRPGUI_BIN=result/bin/ttrpgui` points `bun run smoke`'s script at it.
- `bun run check` (tsc and Biome), `bun test` (unit tests), `nix fmt`. Biome reads `biome.json` in both.
- `bunx shadcn add <name>`: add a shadcn/ui component (`components.json` configures it).

## Screenshots and UI checks

NEVER open windows on the user's desktop. Browsers run headless; Electron runs under Xvfb. Tests and scripts MUST NOT touch the real config or state directories: `bootGame` uses a temp config file, and the smoke check sets temp XDG directories. Electron runs without `DBUS_SESSION_BUS_ADDRESS` and `WAYLAND_DISPLAY`, with `dialog.showOpenDialog` stubbed in the main process: the folder picker reaches the real desktop through its portal. Discovery in tests uses `TTRPGUI_DISCOVER`, never the LAN or port 7373.

- `bun run shots [fixture] [outDir]`: builds, serves a temp copy of `fixtures/<fixture>` (default `sample-game`), and writes `shots/control.png` (1280x800) and `shots/display.png` (1920x1080). `shots/` is gitignored.
- `bun run smoke`: launches the real Electron app under `xvfb-run` with no session bus: the start page, opening a Game from it (the folder picker stubbed in the main process), the display window and its music, and joining a flag-started display host from a second instance's start page. It writes `shots/electron-control.png` and `shots/electron-display.png`.
- Display checks: drive both pages from one script. The harness browser runs with `--mute-audio`, so media plays silently and `audio.currentTime` advances; it blocks sound until a click, so first click `getByRole("button", { name: "Click to start the music" })`. Each fixture track lasts 6 seconds. Check 1920x1080 and 2560x1440 (`display.setViewportSize`). Test sync against a fake `yt-dlp` on PATH, or the real one with a short `wallpaper_section` and `ytdlp_args = ["--playlist-items", "1-2"]` in the temp config.
- Custom checks: write a script that imports `harness/harness.ts` and run it with `node` after `bun run build`.

```ts
import { bootGame, openViews } from "./harness/harness.ts";
const game = await bootGame(); // { gameDir, configFile, url, close }: temp copies you may edit
const { browser, control, display } = await openViews(game.url); // Playwright pages, already connected
await control.getByText("Cinder Drake").waitFor();
await control.screenshot({ path: "shots/x.png" });
await browser.close();
await game.close();
```
